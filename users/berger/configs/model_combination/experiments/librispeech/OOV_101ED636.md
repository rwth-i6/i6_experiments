The native-decoder smoke job has 34 cases, including the original topology
checks, zero-cost IV utterances, alpha's `n-1` convention, known-pronunciation
refunds, extended ordinary UNK lemmata, beta in legacy mode, neutral separators,
and four RNA checks. Forced-path toy tests are not an exhaustive proof for real
model scores. These new native checks must execute on the new binary; Python
unit tests of their job graph are not evidence that the decoder passed them.

The acoustic diagnostic samples 32 sequences evenly across dev-other's sorted
order (rather than taking only the shortest utterances), using the same OggZip data
as Granite recognition, float32, no preemphasis, and no peak normalization. It
forces the lowercased reference token sequence with exact CTC Viterbi DP (no LM,
no beam). For each marked token with an exact unmarked counterpart, it records
`cost(unmarked) - cost(marked)` at the strongest aligned emission frame and
summed across its aligned span. Missing counterparts are counted explicitly.
This is conditional on the reference casing/tokenization, not a comparison of
all possible normalized reference variants. Failure to align is a diagnostic
failure, not silently omitted data.

The scoring audit reads explicit, completed 5083edde Granite job paths at 4-gram
scale 0.3 (closed and known-excluding, beta 0, beam 256). It verifies an acoustic
no-op scorer and hence zero word-exit cost. Per-word LM increments exclude EOS,
specials, and neutral punctuation. Lexical piece length gives each lemma equal
weight, averaging its pronunciation variants. Alpha_0 is a starting heuristic,
not an optimum; it uses the already scaled LM cost, so do not multiply by 0.3
again. The selected old open run need not exhibit sentence collapse: the report
records what actually happened, not an assumption that every fallback run failed.

## Important distinction: scoring versus pruning

101ed636 adds alpha and route-independent beta, **not beta lookahead**. It can
address a final-score preference for long Granite words, but that is separate
from the demonstrated BPE late-beta pruning failure. In the latter, the pinned
5083edde decoder returned a path costing 963.29 instead of an available closed
path costing 302.12 on segment 7601-291468-0000. This cannot be explained by the
winning final score. Wider beam alone did not fix the synthetic reproduction;
widening the score threshold did. Do not relabel that observation as a pure
scoring preference, and do not assume this commit fixes it automatically.
The separate four-condition delayed-penalty probe reruns that counterexample on
the new binary, without requiring the narrow-beam failure to remain forever.

Alpha itself is provisional on known prefixes and is later refunded. This too
can influence finite-beam pruning even though complete known paths have equal
scores. Compare score-threshold operating points as well as beam sizes if the
known-path equivalence is lost with real acoustic inputs.

## Enabling WER phases after reviewing preflight

These entry points are implemented but deliberately **not called by run_all**:

- `run_granite_phase(alpha0_by_lm=..., lm_conditions=..., phase="comparison")`
- `run_granite_phase(..., phase="sweep", betas=...)`
- `run_bpe_phase(model, kind="bpe", ..., phase="comparison" | "sweep")`
- `run_bpe_phase(model, kind="transducer", ..., phase="comparison" | "sweep")`

`lm_conditions` maps unique names (including LM scale and adaptation condition)
to one `ArpaLmParams`, one `TransformerLmParams`, or `None`. No subword LM is
added. `alpha0_by_lm` must explicitly supply each condition's calibrated value;
missing/nonfinite values fail. Reuse `OovScoringBalanceJob` with the appropriate
model's baseline logs to calibrate other LMs/scales, rather than copying Granite
4-gram's alpha to the BPE or Transformer conditions. For no-LM experiments,
declare the chosen reference alpha explicitly (its own mean LM cost is zero).

The comparison uses beta 0, alpha_0 for known-excluding, and matched beams 256 and
1024 at score threshold 16; it also adds a same-build greedy reference. Beam
1024 is a convergence probe, not a claim of matched quality. The sweep uses
alpha_0 times `[0.5, 0.75, 1, 1.5, 2]` and configurable beta values, defaulting to
`[-4, -2, -1, 0, 1, 2, 4]`. Approach A and legacy sweep beta only. Closed controls
remain at zero penalties. No prior, blank penalty, word-exit reward, or subword
LM changes are bundled with these factors. Existing positive-beta BPE results
can motivate supplying a different beta grid. Original/adapted word LMs must be
separate calls/condition names with separate calibration, not bundled changes.

Granite approaches:

- Closed: standard single-surface-word lexicon, no fallback entries.
- A-100k / A-300k / A-full: candidates from LM training text, ranked by frequency
  with lexical tie breaking, excluding existing lexicon and ARPA vocabulary.
  New ordinary entries have their own orthography and singleton `<UNK>` syntax.
- B: the closed lexicon plus known-excluding fallback.
- C-100k / C-300k / C-full: the corresponding extension plus fallback.

All share the acoustic inventory in model order. Candidate tokenizations use
lower/title/uppercase variants; unrepresentable or cross-word pronunciations
are rejected and reported. No dev/test reference words enter candidate selection.
Limits refer to ranked candidates considered, not a promise of that many usable
new lemmata. Preparation time/counts/rejections are registered. Tree-build
memory/time still need to be measured from the actual recognition jobs before
choosing a large extension; lexicon preparation time is **not** tree-build time.

BPE CTC and RNA use standard plus 1/1.5/2/3% reduced lexica. Closed, legacy and
known-excluding consume the same validated XML per target. Final orths are
explicitly refreshed with `&&` to avoid old cached, unmarked fallback files.
Both modes get exactly the same beta axis; alpha applies only to known-excluding.

All tree lexica are gated on successful correctness, acoustic-margin and scoring
audits. State-tying and ARPA-UNK checks are reused on the new binary. All full
recognition calls are dev-other only. Held-out evaluation is not scheduled.

## Degeneracy checks and remaining analysis

Every new fallback variant uses `GuardedOovTracebackFormatter`, which checks the
selected trace before CTM generation. It prints `OOV_DIAGNOSTIC` JSON with
cumulative mean recognized/reference words, fraction of <=2-word hypotheses,
fallback lexical matches, and maximum pieces in a non-attested fallback word.
Defaults fail on an unknown word longer than 64 pieces, or (for references of at
least 10 raw words) <=2 recognized words or a recognized/reference ratio below
0.5. These conservative, explicit guardrails may flag a legitimate outlier;
review the traceback instead of silently relaxing them. They use raw word
boundaries, not normalized prefixes. Byte fallback detokenizes with the actual
tokenizer through the existing Granite formatter.

CTM/Sclite I/D/S, runtime and active-hypothesis outputs remain registered by the
recognition pipeline. Paired IV/OOV and adjacent-IV-error analyses must be run
once these conditions finish, using a fixed partition from the **original**
lexicon, not a partition that moves when A adds a word. HF normalization expands
some words and its compound rule can alter alignment units, so raw-route counts
must not be equated with normalized-word accuracy.

The binding does not expose the actual per-word LM token/route decision. A piece
trace matching a known pronunciation is expected to resolve to the known token;
the guard reports that match but cannot independently assert that RASR used that
token. Extended ordinary entries legitimately use UNK, even on an exact lexical
match. The smoke checks verify these score semantics on controlled examples;
an exhaustive real-run "no wrong UNK route" assertion needs per-word LM-event
instrumentation in RASR. Beam-wide event counters cannot substitute for it.

Not yet executed: the new build's native acceptance cases, GPU acoustic margins,
the full A/B/C grids, tree resource measurements, or post-run paired analyses.
