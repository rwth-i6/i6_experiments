source build of the pinned commit, and every environment.yml pin resolved unchanged. The concern:
**librosa is missing from environment.yml**, and i6_core imports it unconditionally

package's tests fail, 4 of them at collection. I did not install librosa (the brief said not to fix
failures); a dry run shows it would install without changing any pin (below).

## Deviations from the pins and from the reference

- **environment.yml pins: none changed.** All conda pins solved on linux-64 as written, with
  `CONDA_OVERRIDE_CUDA=12.6` because glukose has no GPU driver. Resolved builds: pytorch
  `2.7.1 cuda126_mkl_py311_hcada2b2_300`, pytorch-gpu `cuda126_mkl_ha999a5f_300`, ffmpeg
  `7.1.1 gpl_h5c0ada0_711`, libvorbis 1.3.7 `h54a6638_2`, libogg 1.3.5 `hd0c01bc_1`, cudnn 9.10.2.21,
  nccl 2.30.7.1, cuda-cudart 12.6.77. All pip pins are installed at their exact versions. conda
  first pulled fsspec 2026.7.0 as a dependency; pip then replaced it with the pinned 2026.2.0.
- **Platform differences the yml leaves to the solver:** BLAS is MKL (`libblas 3.9.0 37_h5875eb1_mkl`),
  while the reference used OpenBLAS; `_openmp_mutex` is `8_kmp_llvm`, as on the reference.
  libstdcxx/libgcc are 16.2.0.
- **k2:** a source build, not a wheel, so the commit is exact. Its version string carries the build
  date (dev20260924; the reference is dev20260921). Arches are 70 and 86, not 90. **k2's candidate
  list at this commit has no 89** (for CUDA 12.6 it is 50 60 61 70 75 80 86 90), so "70;86;89"
  cannot be built. sm_86 SASS runs on sm_89, which the L40S check confirms. There is no PTX, so the
  other i6 GPUs are **not** supported by this k2: GTX 1080/Titan X Pascal sm_61 and RTX 2080 sm_75
  (gpu_11gb), and A100 sm_80 (log_gpu_80gb). Adding 75 and 80 would need a rebuild with
  `CUDA_GPU_DETECT_OUTPUT='7.0 7.5 8.0 8.6'`.
- **Build-environment changes needed for k2**, compared with env/build_k2.sh (all are in
  `/work/asr4/hwu/tools/build_k2_i6.sh`, reproduced below):
  1. `build_k2.sh` rejects more than one arch (`CUDA_ARCH` must match `^[0-9]{2,3}$`), so its steps
     were run by hand, with `CMAKE_CUDA_ARCHITECTURES='70;86'`, `CUDA_GPU_DETECT_OUTPUT='7.0 8.6'` and
     `TORCH_CUDA_ARCH_LIST=7.0;8.6`.
  2. `CPATH=$CUDA_HOME/include`. Without it the host `.cc` files fail with
     `nvtx3/nvToolsExt.h: No such file or directory`: k2 defines K2_USE_NVTX3 for CUDA 12.6 or later,
     but CMake gives the host compiler no CUDA include dir. On JUPITER the CUDA module presumably
     supplies it. Log: `/work/asr4/hwu/tmp_probe/env_build/step3_k2_build_attempt1_nvtx.log`.
  3. `-Wl,-rpath-link,$ENV/lib` added to the exe and shared linker flags. Without it, linking the
     `k2/torch/bin` executables fails with undefined cudnn and LAPACK symbols: libtorch's own
     NEEDED libraries (MKL, libcudnn.so.9, nccl, cudss, libomp) are in the env's `lib/`, and ld does
     not search `-L` dirs for transitive dependencies. This change is link-time only. Log:
     `step3_k2_build_attempt2_rpathlink.log`.
  4. The toolchain is system gcc/g++ 11.4, system cmake 3.22.1 and the system CUDA 12.6.68 toolkit
     (`/usr/local/cuda-12.6`), with `$CUDA_HOME/bin` ahead of the env on PATH. The env carries a bare
     `cuda-nvcc-tools` 12.6.85 nvcc, pulled in by pytorch, without CUDA dev headers.
  - As on JUPITER, the final build was **incremental over the failed attempts in one build
    directory**. A clean build with the final script has not been run.
- **KenLM:** built with the conda-forge toolchain in the separate env `kenlm_build`: gcc/g++ 15.3.0,
  cmake 4.4.3, libboost-devel 1.88.0 (below 1.89 because KenLM asks for the `system` component),
  eigen 3.4.0 (pinned down from 5.0.1 for KenLM's `Eigen3 3.1.0` check), zlib 1.3.2, bzip2 1.0.8
  and xz 5.8.3. The sae env is untouched.
- **sequitur:** built exactly as install_env.sh step 2 does it. PyPI has a manylinux x86_64
  `swig==3.0.12` wheel, so `/work/asr4/hwu/swig-3.0.12` was not needed.
- **Facts differing from the brief:** the V100 node cn-32 runs NVIDIA driver 580.173.02, not

  `4537aaf2` (README `ca161b7d`, which is an ancestor), RETURNN is `5f752be4` (README `00171dfe` plus

`/work/asr4/hwu/tools/build_k2_i6.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail
K2_ENV=/work/asr4/hwu/conda/envs/sae
K2_SRC_DIR=/work/asr4/hwu/tools/k2_src_ec31d2c9
K2_COMMIT=ec31d2c96e04665eadb276ebcfd436892f74b0aa
MAKE_JOBS="${MAKE_JOBS:-12}"
export CUDA_HOME=/usr/local/cuda-12.6
CC="$(command -v gcc)"; CXX="$(command -v g++)"; export CC CXX
export CUDACXX="$CUDA_HOME/bin/nvcc" CMAKE_CUDA_COMPILER="$CUDA_HOME/bin/nvcc"
export CMAKE_CUDA_ARCHITECTURES="70;86" TORCH_CUDA_ARCH_LIST="7.0;8.6"
export MAKEFLAGS="-j$MAKE_JOBS" K2_MAKE_ARGS="-j$MAKE_JOBS"
export PATH="$CUDA_HOME/bin:$K2_ENV/bin:$PATH"
export CPATH="$CUDA_HOME/include${CPATH:+:$CPATH}"
export K2_CMAKE_ARGS="-UTORCH_LIBRARY -DCMAKE_BUILD_TYPE=Release \
 -DK2_ENABLE_TESTS=OFF -DK2_ENABLE_BENCHMARK=OFF -DK2_BUILD_FOR_ALL_ARCHS=OFF \
 -DCUDA_GPU_DETECT_OUTPUT='7.0 8.6' -DCMAKE_CUDA_ARCHITECTURES='70;86' \
 -DCMAKE_CUDA_COMPILER=$CUDA_HOME/bin/nvcc -DCMAKE_CUDA_HOST_COMPILER=$CXX \
 -DCMAKE_C_COMPILER=$CC -DCMAKE_CXX_COMPILER=$CXX \
 -DPYTHON_EXECUTABLE=$K2_ENV/bin/python \
 -DCMAKE_EXE_LINKER_FLAGS='-L$K2_ENV/lib -Wl,-rpath-link,$K2_ENV/lib' \
 -DCMAKE_SHARED_LINKER_FLAGS='-L$K2_ENV/lib -Wl,-rpath-link,$K2_ENV/lib'"
[[ "$(git -C "$K2_SRC_DIR" rev-parse HEAD)" == "$K2_COMMIT" ]] || exit 1
(cd "$K2_SRC_DIR" && "$K2_ENV/bin/python" setup.py install)
```
